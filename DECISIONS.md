# Decision log

Choices about fantasy-web that the code shows but cannot explain, one line each. The format and
the rules live in the monorepo root `DECISIONS.md`; decisions that span repos go there instead.

---

[2026-09-10] fantasy-web: icons are drawn by `@ng-icons/lucide` behind `<app-icon>`, not hand-copied into a template — copying each new icon by hand is how the set drifted to six stroke widths; `lucide-angular` was rejected because its peer range stops at Angular 21, and the earlier claim (#591) that this ruled out a package was wrong, since `@ng-icons/lucide` supports Angular 22.
[2026-09-10] fantasy-web: the "From scratch" starting point uses `square-dashed`, not `pencil` or a new-file icon — the pencil already means "edit" (change a pick, rename a projection), and all three cards create a projection, so what sets this one apart is that it starts empty.
[2026-09-11] fantasy-web: the note under the AI projection preview names its data source and not its method — the old line described a three-season, age-adjusted blend, which left out most of what the model now does (fitted availability, league level, finishing table, depth charts) and would go stale with every model version, while the MoneyPuck credit is the part the terms actually require.
[2026-09-11] fantasy-web: "Import league" uses Lucide's `import` (an arrow into a tray), not `refresh` or `download` — `refresh` stays with what genuinely syncs again ("Re-sync or change league", the player list notice), so importing and re-syncing no longer look like the same action, and `download` reads as saving a file to the user's machine, when this pulls settings into the app.
[2026-09-11] fantasy-web: icon sizes are a type (`IconSize`: 14, 16, 20, 48 or an `em` length), not a documented scale — with only the prose, the app drifted to 12, 13, 15, 18 and 22 as well; buttons and menus went from 15 up to 16 rather than down to 14, because 14 is the size for an icon inside running text, and 48 joined the scale because both empty and error states already used it on purpose.
[2026-09-11] fantasy-web: the AI projection preset follows the BFF's `GET /api/v1/features` (`FeatureService.aiProjection`) and the `AI_PROJECTION_ENABLED` build arg is gone — a web switch next to the BFF's had to agree with it by hand, and prod-web had it on while prod-bff refused the model; keeping the build arg as an extra kill switch was rejected because the BFF's `AI_PROJECTION_ENABLED` already turns the feature off everywhere without a web rebuild, and no deployed web app set it.
[2026-09-11] fantasy-web: the preset-draft E2E waits for the "Start a new draft" section to know the sources loaded, not for the Start button — the button is replaced by "Unlock with Premium" whenever the picked preset is locked, which is correct product behaviour; discarding the shared account's preset draft each run (so the start path runs daily) was passed over for now, since it adds a destructive step to a shared account for coverage the happy path's projection draft mostly gives.
[2026-09-11] fantasy-web: a line whose skater/goalie type disagrees with the pool is restarted from the player's own pool line (`squaredWithPool`, where the editor loads a board and where the starting-point preview ranks one), not guarded with `?? 0` in the cell or squared in the BFF reconciler — the model reads a player's type from the NHL and the pool from ESPN, which lists goalie Arsenii Sergeev as a centre, so the two will disagree again; a zero-filled cell would draw a goalie's line under skater columns and rank it as a goalie, and the reconciler never looks at rows it did not add.
[2026-09-11] fantasy-web: staging is kept out of search by an `X-Robots-Tag: noindex` header that nginx sends whenever `APP_ENV` is not `production`, not by a staging robots.txt with `Disallow: /` — a crawler has to fetch a page to learn it must drop it, so a Disallow would leave whatever staging already has indexed; keying on "not production" rather than "is staging" means a new environment starts hidden, at the price that a mistyped prod value hides prod, which DEPLOYMENT.md now warns about.
[2026-09-11] fantasy-web: nginx caches only js and css for a year as immutable, and images, icons and fonts for a day — the build hashes every script and stylesheet name, but the files in public/ keep a fixed name, so a year's cache kept a replaced favicon from anyone who had visited; a day was picked over `no-cache` so the logos on every page do not cost a revalidation request each load.
[2026-09-11] fantasy-web: a page is kept out of search by the noindex the app sets on every route not marked `indexable`, not by robots.txt — a Disallow stops the crawl but leaves an already-indexed URL listed, as /forgot-password was; a default-deny robots.txt would also block the bundle Googlebot renders with and the `/s/` links X's preview bot must reach, and an nginx X-Robots-Tag per path was passed over as a third list of routes to keep in step, so crawl-rules.spec.ts holds sitemap.xml and robots.txt to the route data instead.
[2026-09-11] fantasy-web: Paddle's environment is read off the client token's prefix (`test_` sandbox, `live_` production), not set by a `PADDLE_ENVIRONMENT` build arg — the arg could only agree with the token or contradict it, and left unset it silently meant production; a token of any other shape is reported as a build fault rather than defaulted to either account.
[2026-09-11] fantasy-web: `/pay` opens Paddle's one-page checkout, not its default multi-page one — the BFF now attaches the buyer's verified email, which leaves a separate email step with nothing to ask; the overlay mode is stated too rather than inherited from Paddle's defaults.
[2026-09-11] fantasy-web: the welcome after checkout is only the thanks, with no "Start an AI projection" / "Pick a range on Who's Hot" buttons — removed at Alexander's call, which also dropped `link`/`linkLabel` from `PremiumPerk` since nothing else read them; hiding the buttons but keeping the fields was passed over as data nothing reads.
[2026-09-11] fantasy-web: the two plan cards on /premium share their rows through CSS subgrid (head, perks, plan state, action, small print), not bottom-pushed footers or a fixed note height — pushing the action down lined the cards' last lines up, so a two-line note under one action and a one-line note under the other left the actions a line apart, and a min-height would hold only for the copy it was measured against; every action on the cards is a `btn-lg`, the size the "Your current plan" box was already drawn to.
[2026-09-11] fantasy-web: while Paddle's price preview loads, /premium says "Loading price" inside a price row held at the amount's own line height, and the free card's figure stays empty until the same answer arrives — the old stand-in line was shorter than the price, so its swap pushed both cards down, and "Free" turning into "0 kr" a beat later was a second jump; hiding the whole head until the price arrived was passed over because Paddle can fail or be slow, and the line that says the price is confirmed at checkout stays as the fallback once it has.
[2026-09-11] fantasy-web: Who's hot takes each season's length and its opening season from the BFF's `/projection-model/splits/seasons`, sends "Last N" as `lastGames`, and remembers a season only once the visitor picks one (settings version 3), replacing `SEASON_SCHEDULE_GAMES = 82`, `DEFAULT_SEASON_START_YEAR = 2025` and from/to pairs counted back from the schedule's end — 2026-27 is 84 games, mid-season each team stands on its own game number, and version 2 saved the season on every visit so a summer visit would have held the page on 2025-26 all winter; a web-side table of season lengths was rejected as a fourth copy of projection-service's rule.
[2026-09-11] fantasy-web: the Who's Hot "Min. games" box shows the minimum the user chose and is capped by the season, not the range; only the table's filter is clamped to the range's length (`appliedMinGames`) — #526 showed the clamped figure in the box so it always matched the running filter, but a setting that changes by itself when the range moves read as the page overriding the user (Alexander's call); dropping the clamp altogether was passed over because a minimum above the range's length empties the leaderboard with nothing on screen saying why.
